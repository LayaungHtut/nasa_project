# Monsoon-season time series (Track 40 / Frame 10)

The original case study compared two NISAR passes, August 27 and September 8, 2026. NISAR images the same ground every 12 days, so this record follows the same 14 km Hlawga study area through every Track 40 / Frame 10 GCOV pass on ASF, as of 2026-11-12.

## Method

- **Search:** `asf_search` for NISAR GCOV intersecting the AOI center, filtered to path 40 and frame 10. All passes share the 23:02:39 UTC (05:32 Myanmar time) acquisition time and the same 10 m UTM grid. The script asserts the grid is identical for every date.
- **Reading:** the two original granules are read from `data/raw/`. Every other date is read through `services/processing/remote_gcov.py`: HTTP range requests fetch only the HDF5 chunks covering the 1,400 × 1,400-pixel window, about 0.17% of each roughly 6 GB granule's grid. No full granule is downloaded.
- **Processing:** identical to the served event: HH (`HHHH`), 3 × 3 Lee filter, dB conversion, and the same -9.54 dB water threshold. The script checks that the August 27 and September 8 water-pixel counts equal `statistics.json` exactly, so the series and the event cannot drift apart.
- **Land cover:** ESA WorldCover 2021 v200 (10 m), sampled nearest-neighbour onto the radar grid. The paddy, reservoir and built-up regions therefore come from an independent map, not from the radar being analysed. WorldCover "cropland" is used for paddy; around Hlawga this is overwhelmingly rice land, but the map does not name the crop.
- **Core masks:** class statistics use WorldCover pixels eroded by 2 px (20 m), so mixed pixels at field edges and the shoreline do not blur the classes. `erosion_sensitivity_max_db` records how far each class median moves against the full mask: at most 0.38 dB for paddy and 0.17 dB for the reservoir. Water-like _areas_ still use the full class.
- **Land-cover layer:** only paddy, reservoir and built-up land are coloured, in the same colours as the charts. On a map every colour must stay distinct from every other, and three is the most a colourblind-safe palette supports, so forest and grassland stay clear and the radar image shows through. Only the WorldCover tiles that cover the study area are decoded (the full tile would need 1.3 GB of memory); regenerating the record with this windowed read left every existing value unchanged.
- **Per-pixel test with a control:** medians can hide a few strongly changing fields, so `pixel_season` tests every 70 m neighbourhood (7 x 7 mean) on the passes that share one processing version. Forest goes through the same tests: it should change little over weeks, so its pass rate is the false-positive rate from speckle and calibration. For this test the cores are eroded to 3 px, so no smoothing window mixes classes (a unit test caught the earlier 2 px version leaking paddy signal into forest edges).
- **Stability reference:** built-up land should change little between passes. Its median HH range across dates shows how much of any change could come from calibration or processing rather than the ground.
- **Weather:** ERA5 (Open-Meteo) and Yangon airport METAR at every pass, using the same code as `docs/science/weather-check.md`. Raw responses are saved in `data/validation/yangon-track40-frame10/weather/series-*`.

## Reproduce

```sh
# Earthdata Login credentials in .env; WorldCover tile in data/raw/worldcover/ (URL in the script docstring)
python -m services.processing.timeseries --event-id yangon-track40-frame10
```

Writes `data/processed/yangon-track40-frame10/timeseries.json`, one HH quicklook per date, the field-timing map, and the land-cover layer (`landcover.png`) with the two-date water loss (`water_loss.png`) in `timeseries/`, on the event's shared -15 to +5 dB display range. Each window is cached in `data/raw/timeseries_cache/`, so a rerun takes about 20 seconds; remote reads time out and retry instead of hanging.

```sh
python -m services.processing.ndvi --event-id yangon-track40-frame10      # Sentinel-2 check, no login needed
python scripts/compare_processing_versions.py --event-id yangon-track40-frame10
python -m pytest tests/test_timeseries.py                                  # per-pixel test on a synthetic scene
```

On Windows machines where Application Control blocks h5py's DLLs, `io_gcov.py` falls back to `pyfive`, a pure-Python HDF5 reader (`pip install pyfive`).

## Findings (12 passes, June 16 to November 7, 2026)

All values are from `timeseries.json` and the validation records named below. The app computes its text from the same records, and tests in `src/lib/data/timeseries.spec.ts` fail if the claims stop matching them.

1. **A scene-wide offset changes from pass to pass.** Forest, grassland, paddy, built-up land and the reservoir brighten and darken together by up to about 2 dB. Across the 10 passes with the same processing, forest brightness follows the previous 24 hours of rain (correlation 0.69). That fits rain-wetted surfaces reflecting more radar energy, but a calibration contribution in these provisional products cannot be excluded. Comparing each class with forest removes most of the offset: built-up minus forest stays within 0.57 dB over those 10 passes.
2. **The processing version changed mid-season, and we traced what changed.** The October 26 and November 7 granules are `NISAR_L2_GCOV_V1` (CRID P05036, product 1.0.20, software `release-r05.03.5`); the earlier ten are provisional (P05023, product 1.0.11, `pge_r05.02.3`). Absolute HH drops about 2 dB in every class, so the fixed -9.54 dB threshold does not transfer: their 20 to 23 km² "water" areas are a processing effect, and the app does not plot them as comparable. `scripts/compare_processing_versions.py` reads both products' metadata (`data/validation/yangon-track40-frame10/processing-versions.json`): every processing flag is identical, noise correction is off in both, the noise floor over the study area is unchanged (-22.5 and -23.9 dB), and the run configurations differ only in DEM version (1.2 to 1.3) and ionosphere options. Relative to forest, paddy moves by -0.25 dB and built-up by +0.62 dB across the change, but the reservoir drops by 5.4 dB (see finding 6).
3. **The 4.517 km² "apparent water loss" lies on paddy fields, not the reservoir.** Recomputed from the event's own `baseline_db.npy` / `post_event_db.npy` (pixel counts equal `statistics.json`), 4.149 km² (92%) of the loss falls on WorldCover cropland and only 0.031 km² on permanent water. Of the 0.056 km² new-inundation candidate, 0.050 km² is cropland. This answers the question left open in [real-data-validation.md](real-data-validation.md): the change between August 27 and September 8 is the rice fields, not reservoir drawdown and not wind on the reservoir.
4. **A rice-season curve.** Relative to forest, paddy fields sit between -3.9 and -3.5 dB from June to mid-August and are darkest on August 27 (-4.35 dB). On that date 7.9% of cropland pixels fall below the water threshold, consistent with flooded fields. They then brighten steadily to -2.31 dB on October 14 (+2.0 dB). That is the expected L-band HH behaviour as rice stems grow above standing water (double-bounce scattering). The two V1 passes read -2.56 and -2.78 dB, which could be the start of harvest, but the version change alone moves paddy by 0.25 dB, so it is not claimed.
5. **The rise is widespread and specific to the fields.** Between August 27 and October 14, 72% of paddy neighbourhoods brightened by more than 1 dB against forest, versus 4.2% of forest neighbourhoods (the control); 1.7% of paddy darkened by as much. Over the season, 82% of paddy shows a darkest pass followed by a rise of at least 1.5 dB, against 12% of forest by chance. The app's **Field Timing** layer (`timeseries/darkest_pass.png`) maps the date of each field's darkest pass: 17.1 km² were darkest June 16 to July 22, 21.0 km² from August 15 to September 8, and 0.1 km² later. Timing forms patches: paddy pixels 150 m apart (beyond the smoothing window) share a timing group 67% of the time, against 50% for spatially random labels. That fits fields planted at different times, though a local shower on one date could also create patches.
6. **The reservoir is persistently bright; wind does not explain it, and part of it is likely processing.** Its median HH stays between -9.0 and -4.4 dB on all 10 comparable passes, against roughly -20 dB or lower usually expected for calm open water at L-band. ERA5 wind was 1.5 to 3.7 m/s at every pass, and reservoir brightness relative to forest is uncorrelated with it (correlation -0.02). In the V1 products the reservoir reads 5.4 dB darker relative to forest while land moves under 0.7 dB, so part of its brightness in the provisional products likely comes from processing. Even in V1 it reads -13.4 dB, still about 10 dB above the noise floor, so floating or emergent vegetation remains a candidate. It has not been checked on the ground.
7. **Sentinel-2 neither confirms nor contradicts the radar rise.** `services/processing/ndvi.py` reads Sentinel-2 L2A red and near-infrared (Earth Search, tile 46QHD) on the same land-cover cores. It keeps scenes where at least half of the paddy is cloud-free by the scene classification layer. Only 8 of 37 scenes from June 16 to November 7 qualify, and none between August 7 and September 12, so no clear optical view exists near the radar's darkest date. On those 8 dates paddy NDVI is already 0.60 to 0.71, and paddy minus forest stays between -0.20 and -0.17. Optical greenness levels off once a canopy closes, while L-band keeps responding to stems and grain. So the optical data are consistent with the radar but are not independent confirmation of growth. (Earth Search lists a -0.1 reflectance offset on its bands even where `earthsearch:boa_offset_applied` says it has already been removed. Applying it twice gives NDVI above 1, so the script checks that flag.) Record: `data/validation/yangon-track40-frame10/ndvi-series.json`.

## Limits

- Ten comparable passes is a short series; correlations are indicative, not statistically established.
- WorldCover 2021 is five years older than the radar and labels cropland, not rice; field boundaries and the reservoir shoreline may have shifted.
- No crop calendar, field survey or reservoir level record has been checked. These would confirm or refute findings 3 to 6. Planting dates from farmers around Hlawga would test the Field Timing map directly.
- Built-up core and full-mask medians differ by about 1 dB (mixed edge pixels). Built-up is used only for its range across dates, which a constant difference does not affect.
- The cause of the V1 shift lies upstream of GCOV and is not recorded in the product metadata; only the size of the shift per class is measured here.
